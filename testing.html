Раздел 9

Тесты: как менять код и ничего не сломать

Тест — это маленькая программа, которая проверяет вашу программу. Он за секунды находит то, что вручную пришлось бы прокликивать.

Как устроен тест

Почти любой тест состоит из трёх частей: подготовить данные, выполнить действие, проверить результат.

Простейшие проверки через assert 
def add_vat(price, rate=0.12):
    return round(price * (1 + rate), 2)

def test_add_vat():
    assert add_vat(100) == 112.0

def test_custom_rate():
    assert add_vat(200, rate=0.2) == 240.0

test_add_vat()
test_custom_rate()
print("Все тесты прошли")

Измените в примере ожидаемое значение и запустите снова: вы увидите, как выглядит упавший тест.

pytest

Самая популярная библиотека тестов на Python. Она сама находит файлы test_*.py и функции test_*.

Терминал 
pip install pytest
pytest
pytest -k vat
pytest -x
test_prices.py 
import pytest

from prices import add_vat

@pytest.mark.parametrize("price, expected", [
    (100, 112.0),
    (0, 0.0),
    (19.99, 22.39),
])
def test_add_vat(price, expected):
    assert add_vat(price) == expected

def test_negative_price():
    with pytest.raises(ValueError):
        add_vat(-1)

parametrize запускает один тест с разными данными. raises проверяет, что код правильно сообщает об ошибке. Во втором тесте функция должна сама отклонять отрицательную цену.

Тесты Flask

Тестовый клиент отправляет запросы приложению без сервера и браузера.

Flask: проверка страницы и API 
from flask import Flask

app = Flask(__name__)

@app.get("/")
def home():
    return "Главная"

@app.get("/api/ping")
def ping():
    return {"status": "ok"}

def test_home():
    response = app.test_client().get("/")
    assert response.status_code == 200
    assert "Главная" in response.text

def test_ping():
    assert app.test_client().get("/api/ping").json == {"status": "ok"}

def test_unknown_page():
    assert app.test_client().get("/nope").status_code == 404

test_home()
test_ping()
test_unknown_page()
print("Все тесты прошли")

В настоящем проекте эти функции лежат в файле test_app.py, а запускает их команда pytest.

Тесты Django

Django создаёт отдельную временную базу, поэтому настоящие данные не пострадают.

tasks/tests.py 
from django.test import TestCase
from django.urls import reverse

from .models import Task

class TaskTests(TestCase):
    def test_list_shows_task(self):
        Task.objects.create(title="Проверить тесты")
        response = self.client.get(reverse("index"))
        self.assertEqual(response.status_code, 200)
        self.assertContains(response, "Проверить тесты")

    def test_add_task(self):
        response = self.client.post(reverse("index"), {"title": "Новая"})
        self.assertRedirects(response, reverse("index"))
        self.assertEqual(Task.objects.count(), 1)
Терминал 
python manage.py test
python manage.py test tasks

Что тестировать в первую очередь

Цель не в стопроцентном покрытии, а в том, чтобы защитить важное.

Стоит проверять

  • Основной сценарий: создать, изменить, удалить
  • Неверные и пустые данные
  • Доступ: чужие данные и страницы без входа
  • Каждую найденную ошибку: сначала тест, потом исправление

Можно не проверять

  • Код самого фреймворка
  • Простые настройки без логики
  • Точное расположение элементов на странице
