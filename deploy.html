Публикация: как выложить приложение в интернет

Пока сервер запущен на вашем компьютере, сайт видите только вы. Разберём, как бесплатно опубликовать список задач из первого проекта на хостинге PythonAnywhere — он создан специально для Python и не требует настройки сервера.

Что получится и какие есть ограничения

После публикации приложение откроется по адресу https://ваш-логин.pythonanywhere.com.

Бесплатный тариф Beginner

  • Одно веб-приложение на адресе логин.pythonanywhere.com
  • 512 МБ на диске — для учебного проекта с SQLite хватает с запасом
  • Приложение работает месяц; затем его нужно продлить кнопкой на вкладке Web
  • Выход в интернет из кода — только к сайтам из разрешённого списка

Порядок действий

  1. Выложить код на GitHub
  2. Скопировать его на PythonAnywhere и установить зависимости
  3. Создать веб-приложение и указать WSGI-файл
  4. Для Django — настроить адрес и статические файлы
  5. Нажать Reload и открыть сайт

Условия тарифа взяты из справки PythonAnywhere на октябрь 2026 года и могут измениться — актуальные данные есть в источниках внизу страницы.

Пошаговая инструкция

В командах замените username на свой логин PythonAnywhere, а USER/REPO — на адрес своего репозитория GitHub.

  1. Шаг 1. Подготовьте проект и выложите его на GitHub

    Файл requirements.txt перечисляет библиотеки проекта — по нему сервер установит то же самое. Файл .gitignore не даёт отправить в репозиторий окружение и локальную базу данных. Репозиторий заранее создайте на github.com.

    Терминал (в папке проекта) 
    pip freeze > requirements.txt
git init
git add .
git commit -m "Первый проект: список задач"
git branch -M main
git remote add origin https://github.com/USER/REPO.git
git push -u origin main
    .gitignore 
    .venv/
__pycache__/
*.db
db.sqlite3
static/

  2. Шаг 2. Скопируйте код на PythonAnywhere

    Зарегистрируйтесь на pythonanywhere.com (тариф Beginner), откройте вкладку Consoles и запустите Bash. Команда mkvirtualenv создаёт окружение и сразу его активирует.

    Терминал (консоль Bash на PythonAnywhere) 
    git clone https://github.com/USER/REPO.git mysite
mkvirtualenv --python=/usr/bin/python3.13 mysite-venv
cd mysite
pip install -r requirements.txt

  3. Шаг 3. Создайте веб-приложение

    На вкладке Web нажмите Add a new web app, выберите Manual configuration (не готовый шаблон Flask или Django — он создаст пустой проект) и ту же версию Python 3.13. Затем в разделе Virtualenv впишите имя mysite-venv — путь дополнится сам.

  4. Шаг 4. Настройте WSGI-файл

    WSGI-файл объясняет серверу, где лежит ваше приложение. Откройте ссылку на него в разделе Code на вкладке Web, удалите всё содержимое и вставьте вариант для своего фреймворка.

    WSGI-файл: Flask 
    import sys

path = "/home/username/mysite"
if path not in sys.path:
    sys.path.insert(0, path)

from app import app as application
    WSGI-файл: Django 
    import os
import sys

path = "/home/username/mysite"
if path not in sys.path:
    sys.path.insert(0, path)

os.environ["DJANGO_SETTINGS_MODULE"] = "mysite.settings"

from django.core.wsgi import get_wsgi_application
application = get_wsgi_application()

    Строка from app import app означает «из файла app.py взять объект app». Если ваш файл называется иначе, исправьте первое слово.

  5. Шаг 5. Только для Django: адрес, база и статика

    В mysite/settings.py выключите режим отладки, разрешите свой адрес и укажите папку для статических файлов — без неё админка откроется без оформления. Затем выполните команды в консоли Bash.

    mysite/settings.py 
    DEBUG = False

ALLOWED_HOSTS = ["username.pythonanywhere.com"]

STATIC_ROOT = BASE_DIR / "static"
    Терминал (консоль Bash на PythonAnywhere) 
    cd ~/mysite
workon mysite-venv
python manage.py migrate
python manage.py collectstatic
python manage.py createsuperuser

    На вкладке Web в разделе Static files добавьте строку: URL /static/, Directory /home/username/mysite/static.

  6. Шаг 6. Перезапустите и проверьте

    Нажмите зелёную кнопку Reload на вкладке Web и откройте https://username.pythonanywhere.com. Если вместо сайта ошибка, откройте Error log на той же вкладке — последняя строка обычно подсказывает причину.

Как обновлять сайт и чего не делать

Терминал: обновление после изменений в коде 
cd ~/mysite
git pull
# для Django, если менялись модели:
python manage.py migrate
# затем кнопка Reload на вкладке Web

Безопасность

  • Не оставляйте DEBUG = True на сервере: при ошибке посетители увидят настройки и куски кода.
  • SECRET_KEY из settings.py не должен лежать в публичном репозитории — храните его в переменной окружения.
  • Не отправляйте на GitHub базу данных с реальными данными — для этого в .gitignore есть *.db.
