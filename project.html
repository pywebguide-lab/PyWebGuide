Первый проект: список задач

Сделаем одно и то же приложение — список задач — двумя способами: на Flask и на Django. Выберите один вариант и пройдите его до конца. На Flask уйдёт около 15 минут, на Django — около 30.

Вариант на Flask Вариант на Django

Что понадобится

Проверьте это до начала — так шаги пройдут без ошибок.

  • Python 3.12 или новее: команда python --version в терминале.
  • Редактор кода, например VS Code.
  • Отдельная пустая папка для проекта, открытая в терминале.
  • Базовый Python: функции, списки, словари (шаг 1 дорожной карты).

Команды для Windows. На macOS и Linux вместо python пишите python3, а виртуальное окружение активируйте командой source .venv/bin/activate. Отмеченные шаги сохраняются в этом браузере — можно вернуться позже и продолжить.

⚪ Flask 3.1 · ~15 минут

Вариант 1. Список задач на Flask

Одно приложение в одном файле: страница со списком и форма добавления задачи.

0 из 4 шагов пройдено

  1. Шаг 1. Создайте окружение и установите Flask

    Виртуальное окружение хранит библиотеки проекта отдельно от остальной системы.

    Терминал 
    python -m venv .venv
.venv\Scripts\activate
pip install flask

  2. Шаг 2. Напишите приложение

    Создайте файл app.py. Задачи пока хранятся в обычном списке — в памяти сервера.

    app.py 
    from flask import Flask, redirect, render_template_string, request, url_for

app = Flask(__name__)
tasks = []

PAGE = """
<!doctype html>
<title>Мои задачи</title>
<h1>Мои задачи</h1>
<form method="post">
  <input name="title" placeholder="Новая задача" required>
  <button>Добавить</button>
</form>
<ul>
  {% for task in tasks %}<li>{{ task }}</li>{% endfor %}
</ul>
"""

@app.route("/", methods=["GET", "POST"])
def index():
    if request.method == "POST":
        tasks.append(request.form["title"])
        return redirect(url_for("index"))
    return render_template_string(PAGE, tasks=tasks)

  3. Шаг 3. Запустите сервер

    Флаг --debug перезапускает сервер при каждом сохранении файла и показывает понятные ошибки.

    Терминал 
    flask --app app run --debug

  4. Шаг 4. Проверьте результат

    Откройте в браузере http://127.0.0.1:5000/ и добавьте пару задач. Обратите внимание: после перезапуска сервера список очищается — данные жили только в памяти. Сохранять их между запусками умеет база данных, это следующий шаг.

Что дальше

  • Вынесите HTML в шаблон templates/index.html и используйте render_template.
  • Сохраняйте задачи в SQLite — пример есть в разделе «О Python».
  • Добавьте кнопку удаления задачи — это отдельный маршрут.
🟢 Django 6.1 · ~30 минут

Вариант 2. Список задач на Django

Задачи хранятся в базе данных SQLite, а добавлять их можно через встроенную админ-панель.

0 из 6 шагов пройдено

  1. Шаг 1. Установите Django и создайте проект

    Точка в конце команды создаёт проект в текущей папке. Затем создаём приложение tasks.

    Терминал 
    python -m venv .venv
.venv\Scripts\activate
pip install django
django-admin startproject mysite .
python manage.py startapp tasks

  2. Шаг 2. Подключите приложение

    В файле mysite/settings.py добавьте "tasks" в конец списка INSTALLED_APPS.

    mysite/settings.py 
    INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "tasks",
]

  3. Шаг 3. Опишите модель и зарегистрируйте её в админке

    Модель — это таблица базы данных, описанная классом Python. ORM сама создаст для неё SQL.

    tasks/models.py 
    from django.db import models

class Task(models.Model):
    title = models.CharField(max_length=200)
    done = models.BooleanField(default=False)

    def __str__(self):
        return self.title
    tasks/admin.py 
    from django.contrib import admin

from .models import Task

admin.site.register(Task)

  4. Шаг 4. Создайте таблицы и администратора

    Миграции переносят модели в базу данных. Последняя команда спросит логин и пароль для входа в админку.

    Терминал 
    python manage.py makemigrations
python manage.py migrate
python manage.py createsuperuser

  5. Шаг 5. Сделайте страницу со списком

    Представление получает задачи из базы, шаблон выводит их списком, маршрут связывает адрес с представлением. Шаблон положите в папку tasks/templates/tasks/ — Django найдёт его сам.

    tasks/views.py 
    from django.shortcuts import render

from .models import Task

def index(request):
    return render(request, "tasks/index.html", {"tasks": Task.objects.all()})
    tasks/templates/tasks/index.html 
    <h1>Мои задачи</h1>
<ul>
  {% for task in tasks %}
    <li>{{ task.title }}{% if task.done %} ✓{% endif %}</li>
  {% empty %}
    <li>Задач пока нет — добавьте их в админке.</li>
  {% endfor %}
</ul>
    mysite/urls.py 
    from django.contrib import admin
from django.urls import path

from tasks import views

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", views.index),
]

  6. Шаг 6. Запустите и проверьте

    Откройте http://127.0.0.1:8000/admin/, войдите и добавьте несколько задач. Затем откройте http://127.0.0.1:8000/ — задачи появятся в списке и сохранятся после перезапуска сервера.

    Терминал 
    python manage.py runserver

Что дальше

  • Добавьте форму на саму страницу, чтобы создавать задачи без админки (класс ModelForm).
  • Выведите отдельно невыполненные задачи: Task.objects.filter(done=False).
  • Пройдите официальное руководство Django — оно продолжает эту же логику на примере опросов.
