Частые вопросы

Короткие ответы на то, что обычно спрашивают новички.

Нужно ли сразу учить Django и Flask?

Нет. Лучше выбрать один фреймворк, сделать на нём простой проект и уже потом сравнивать со вторым.

Можно ли делать сайты без базы данных?

Да, но большинство реальных проектов хранят пользователей, товары или контент, поэтому база данных быстро становится нужна.

Что важнее: теория или практика?

Практика. Теория помогает понимать, что происходит, но навык появляется только после написания кода и разбора ошибок.

Раздел 1

Python как язык серверной разработки

Простой синтаксис, мощная экосистема и зрелые фреймворки делают Python удобным языком для входа в веб-разработку.

Что такое backend-разработка

Backend — это часть приложения, которая работает на сервере: принимает запросы, обрабатывает логику, обращается к базе данных и отправляет ответ.

🌐 Обработка запросов

Фреймворк принимает HTTP-запрос и определяет, какой код должен его обработать.

🗄️ База данных

Приложение читает и сохраняет пользователей, товары, статьи и другие данные через ORM или SQL.

📤 Формирование ответа

Сервер возвращает HTML, JSON или файл — то, что в итоге видит пользователь.

🔐 Логика и безопасность

Проверка данных, права доступа, обработка ошибок и подготовка корректного ответа.

Какие задачи Python решает на сервере

Сервер принимает запросы, работает с данными и возвращает ответы. Вот что для этого делает код на Python.

  • Сопоставляет адрес страницы с нужной функцией (маршрутизация).
  • Проверяет данные, которые прислал пользователь, например из формы.
  • Читает и записывает данные в базу.
  • Проверяет права доступа и вход пользователей.
  • Собирает HTML-страницы из шаблонов.
  • Отдаёт данные в формате JSON для других программ.

Как проходит запрос пользователя

Упрощённая цепочка от клика до ответа сервера.

1

Браузер

Пользователь открывает страницу или отправляет форму.

2

HTTP-запрос

Запрос уходит на сервер: метод, адрес и данные.

3

Фреймворк

Django или Flask находит нужный маршрут и обработчик.

4

Логика и БД

Код проверяет данные, читает или сохраняет информацию.

5

Ответ

Сервер возвращает страницу, JSON или ошибку.

Примеры кода

Минимальный сервер на Flask и базовая работа с SQLite — две важные точки входа.

Flask: минимальный сервер 
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Привет, это Python-сервер!"

if __name__ == "__main__":
    app.run()
SQLite: базовая работа с данными 
import sqlite3

conn = sqlite3.connect("app.db")
cursor = conn.cursor()

cursor.execute(
    "CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)"
)

cursor.execute(
    "INSERT INTO users (name) VALUES ('Айгерим')"
)

conn.commit()
conn.close()

Важно: примеры учебные, сервер в этом проекте не запускается. Код здесь можно только читать и копировать.

Мини-словарь терминов

Понятия, которые помогают увереннее читать материалы по веб-разработке.

Backend

Серверная часть приложения, которая обрабатывает запросы, хранит данные и возвращает ответы.

Frontend

Клиентская часть сайта: интерфейс, кнопки, формы и всё, что пользователь видит в браузере.

HTTP

Протокол, по которому браузер и сервер обмениваются запросами и ответами.

ORM

Инструмент, который позволяет работать с базой данных через объекты и код вместо ручных SQL-запросов.

API

Интерфейс, через который одна программа может получать данные или функции от другой программы.

SQLite

Лёгкая база данных, которая часто используется для учебных и небольших проектов.

Django или Flask: два подхода к одному языку

Оба фреймворка решают одну задачу — построение серверной части сайта, но делают это по-разному: через готовую архитектуру или через гибкое минимальное ядро.

🟢 Django

Django

«Batteries included» — фреймворк с полным набором инструментов.

  • Встроенная ORM для работы с базой данных
  • Готовая админ-панель для управления контентом
  • Строгая структура проекта и единый стиль кода
  • Хорошо подходит для средних и крупных приложений
  • Меньше ручных решений для типовых задач
⚪ Flask

Flask

Микрофреймворк — минимальное ядро и максимум гибкости.

  • Минимум навязанной структуры
  • Расширения подключаются по мере необходимости
  • Проще разобраться с нуля и понять работу сервера
  • Хорош для небольших сервисов, учебных проектов и API
  • Больше контроля над архитектурой

Сравнение по критериям

Семь параметров, по которым чаще всего выбирают фреймворк.

Django и Flask: сравнение по критериям
Критерий Django Flask
Уровень фреймворка Полнофункциональный («всё включено») Микрофреймворк с минимальным ядром
Скорость старта Нужно изучить структуру проекта, зато многое уже готово Первое приложение — за несколько строк
База данных Встроенная ORM и миграции Подключается через расширения и библиотеки
Административная панель Есть из коробки Нет, добавляется отдельно
Гибкость Средняя: есть «правильный путь» Высокая: структуру выбираешь сам
Лучше подходит для Крупных сайтов с пользователями и данными Небольших сервисов, прототипов и API
Пример использования Интернет-магазин, новостной портал Сервис заметок, учебный API

Что выбрать новичку

Короткая подсказка для первого проекта.

  • Хочешь быстро понять, как работает сервер, — начни с Flask: в нём мало «магии».
  • Нужен сайт с пользователями и админкой — бери Django.
  • Оба варианта хороши. Главное — довести первый учебный проект до конца.

Типичные ошибки выбора

Чего лучше избегать.

  • Выбирать по моде, а не по задаче.
  • Брать Flask для большого проекта и вручную собирать то, что в Django уже есть.
  • Брать Django для совсем маленькой страницы.
  • Менять фреймворк, не закончив первый проект.

Когда что использовать

Короткая практическая таблица для выбора фреймворка под задачу.

Рекомендации по выбору между Django и Flask
Задача Рекомендация
Учебный проект и первое знакомство с backend Flask — проще увидеть, как всё работает изнутри.
Сайт с админкой и большим количеством моделей данных Django — админ-панель и ORM экономят время.
Небольшой REST API Flask — минимум лишнего кода.
Проект, который будет расти и поддерживаться командой Django — единая структура снижает хаос в коде.

Частые вопросы

Короткие ответы на типовые вопросы новичков.

Что проще выучить первым?

Если хочется быстро понять, как работает сервер, лучше начать с Flask. Если нужен проект с готовой админкой и базой данных — удобно начинать с Django.

Нужно ли знать SQL?

Желательно. Даже при использовании ORM базовое понимание SQL помогает лучше работать с данными и отлаживать запросы.

Можно ли потом перейти с Flask на Django?

Да. Python остаётся тем же, поэтому переход возможен, но потребуется изучить другую архитектуру проекта и встроенные инструменты Django.

Форма обратной связи

Форма учебная: данные сохраняются только в вашем браузере через localStorage и никуда не передаются.

Серверная отправка не реализована: сообщение остаётся в localStorage этого браузера, его никто не получает.
